# Wallet API

Асинхронный REST API для управления кошельками (финансовыми балансами) пользователей. Разработано на FastAPI с использованием PostgreSQL в качестве СУБД, SQLAlchemy 2.0 (ORM) и Alembic для миграций. Весь проект полностью контейнеризирован с помощью Docker.

## 🚀 Основной стек технологий
* **Python 3.12**
* **FastAPI** (Асинхронный веб-фреймворк)
* **SQLAlchemy 2.0 (Async)** + **asyncpg** (Драйвер БД)
* **PostgreSQL** (СУБД)
* **Alembic** (Миграции базы данных)
* **Pytest** + **HTTPX** (Автоматизированное тестирование)
* **Docker** & **Docker Compose** (Контейнеризация)

## 🛠️ Особенности архитектуры и реализации
1. **Защита от Race Condition (Пессимистические блокировки):** Для предотвращения состояния гонки (когда два параллельных запроса пытаются одновременно списать средства) на уровне СУБД используется механизм `SELECT ... FOR UPDATE` (`with_for_update()` в SQLAlchemy).
2. **Гарантия точности баланса (`Decimal`):** Все финансовые вычисления проводятся с использованием типа данных `Decimal` на стороне Python и `Numeric(12, 2)` на стороне базы данных. Это полностью исключает ошибки округления, свойственные типу `float`.
3. **Целостность данных на уровне БД:** В модели данных зашито проверочное ограничение `CheckConstraint("balance >= 0")`. База данных физически не позволит балансу уйти в минус, даже если запрос пойдет в обход бизнес-логики приложения.
4. **Консистентность окружения:** Все процессы разработки, миграций и тестирования инкапсулированы внутри Docker-контейнеров, что исключает проблемы несовместимости операционных систем (Windows/Linux/macOS).

## 🏗️ Быстрый запуск (Docker)

Все команды выполняются из корневой папки проекта. Перед запуском убедитесь, что вы создали и заполнили файл `.env` (шаблон конфигурации представлен в `.env.example`).

### 1. Сборка и поднятие контейнеров
Запустить всю инфраструктуру (в первый раз или после изменения зависимостей/Dockerfile):
```bash
docker compose up -d --build
```

Если вы просто правите код (он монтируется через volume), достаточно обычного запуска:
```bash
docker compose up -d
```

### 2. Применение миграций базы данных
Миграции применяются вручную при первом запуске или обновлении моделей:
```bash
docker compose exec app alembic upgrade head
```

### 3. Перезапуск приложения
После применения миграций или крупных правок перезапустите веб-приложение:
```bash
docker compose restart app
```

## 📑 Справочник команд для разработки

### Управление контейнерами
* Посмотреть статус контейнеров: `docker compose ps`
* Перезапустить сервис приложения: `docker compose restart app`
* Остановить проект: `docker compose down`
* Полная очистка (остановить и удалить базу данных вместе с volumes): `docker compose down -v`

### Логирование и отладка
* Непрерывный стрим логов приложения: `docker compose logs -f app`
* Просмотр логов базы данных: `docker compose logs db`

### Работа с миграциями (Alembic внутри Docker)
* Проверить текущую ревизию БД: `docker compose exec app alembic current`
* Посмотреть историю миграций: `docker compose exec app alembic history`
* Создать новую миграцию после изменения моделей:
  ```bash
  docker compose exec app alembic revision --autogenerate -m "описание изменений"
  ```
  *(Примечание: если сгенерированный файл пустой — изменения коснулись только Python-уровня, например схем Pydantic или default-значений, миграцию можно удалить).*
* Откатить последнюю миграцию: `docker compose exec app alembic downgrade -1`

### Прямое подключение к PostgreSQL (psql)
* Интерактивная консоль базы данных: `docker compose exec db psql -U postgres -d wallet`
* Быстрый просмотр всех кошельков (для получения UUID при ручном тестировании):
  ```bash
  docker compose exec db psql -U postgres -d wallet -c "SELECT id, balance FROM wallets;"
  ```
* Создать тестовую БД (требуется один раз перед запуском pytest):
  ```bash
  docker compose exec db psql -U postgres -c "CREATE DATABASE wallet_test;"
  ```

## 🧪 Тестирование (Pytest)

Проект покрыт автоматическими тестами, включая проверку валидации данных, граничных значений и устойчивости к конкурентным запросам.

* Запустить все тесты локально на хосте (вне Docker):
  ```bash
  pytest -v
  ```
* Запустить все тесты внутри Docker-контейнера:
  ```bash
  docker compose exec app pytest -v
  ```
* Запустить только тесты на конкурентность (проверка блокировок):
  ```bash
  docker compose exec app pytest -v -k TestConcurrency
  ```
* Запустить один конкретный тест:
  ```bash
  docker compose exec app pytest -v tests/test_wallets.py::TestOperations::test_deposit_increases_balance
  ```

## 📖 Спецификация API (Swagger)

Интерактивная документация со всеми эндпоинтами доступна локально по адресу:  
👉 **[http://localhost:8000/docs](http://localhost:8000/docs)**

### Полный цикл ручной проверки эндпоинтов (E2E Флоу):
1. **Создание кошелька:**  
   `POST /api/v1/wallets` ➡️ Возвращает статус `201`, сгенерированный `id` (UUID) и стартовый `balance: "0.00"`.
2. **Пополнение баланса (DEPOSIT):**  
   `POST /api/v1/wallets/{uuid}/operation` с телом `{"operation_type": "DEPOSIT", "amount": "150.50"}` ➡️ Возвращает статус `201` и обновленный баланс.
3. **Проверка баланса:**  
   `GET /api/v1/wallets/{uuid}` ➡️ Возвращает статус `200` и баланс `"150.50"`.
4. **Попытка избыточного списания:**  
   `POST /api/v1/wallets/{uuid}/operation` с телом `{"operation_type": "WITHDRAW", "amount": "200.00"}` ➡️ Возвращает статус `400 Bad Request` (Недостаточно средств).
5. **Успешное списание (WITHDRAW):**  
   `POST /api/v1/wallets/{uuid}/operation` с телом `{"operation_type": "WITHDRAW", "amount": "50.00"}` ➡️ Возвращает статус `201` и баланс `"100.50"`.
6. **Запрос несуществующего кошелька:**  
   `GET /api/v1/wallets/{рандомный_uuid}` ➡️ Возвращает статус `404 Not Found`.

> ⚠️ **Важно согласно ТЗ:**  
> * Путь для транзакций имеет вид `/operation` (в единственном числе).  
> * Возможные значения для поля `operation_type` строго валидируются и принимаются в верхнем регистре: `DEPOSIT` или `WITHDRAW`.  
> * Сумма `amount` принимает строго до 2 знаков после запятой (передача `10.005` вернет ошибку валидации `422`).
